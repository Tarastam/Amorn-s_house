## ข้อตัดสินใจที่ต้องล็อกก่อนเริ่มเฟส 1

ภาพ 4 ธีมเป็นภาพ AI แบบ 2D isometric ส่วนโค้ดปัจจุบันเป็น 3D voxel (Three.js) สองแบบนี้ผสมกันไม่ได้ เสนอให้ใช้
**ภาพธีมเป็นพื้นหลัง + hotspot คลิกได้** (React/PWA ตามที่ตกลงไว้) โค้ด 3D เดิมเก็บไว้เป็นเอกสารอ้างอิง ไม่ต่อยอด

## เฟสงาน

| เฟส | เป้าหมาย | ส่งมอบ | เสร็จเมื่อ |
|---|---|---|---|
| 0 | ฐานโปรเจกต์ | repo, Pages, สรุปธีม | **เสร็จแล้ว** |
| 1 | แกน task (ไม่ผูกธีม) | data model, to-do/calendar/habits/projects, coin/XP/level, เก็บใน localStorage + ปุ่มสำรอง JSON, หน้าจอแบบ list ธรรมดา | เพิ่ม/ติ๊กงานแล้วได้ XP/coin, รีเฟรชแล้วข้อมูลไม่หาย |
| 2 | ระบบธีม + ธีมแรก | หน้าเลือกธีม (การ์ดไอคอน+ชื่อ), ตัวโหลดธีม (ภาพ + ค่าสี + hotspot), ธีมแรก 1 ธีม | สลับธีมได้ ข้อมูล task ไม่เปลี่ยน |
| 3 | ผูกห้องกับหมวดงาน | hotspot บนภาพแต่ละห้อง เช่น โต๊ะคอม = งานทำงาน, ครัว = งานบ้าน/มื้ออาหาร; คลิกห้องแล้วเปิดรายการงานของห้องนั้น | ทุกหมวดงานมีห้องรองรับ ใช้บนเดสก์ท็อปได้สะดวก |
| 4 | วงจรรางวัล | ใช้ coin ซื้อของตกแต่ง/ปลดล็อกตาม level, ถ้วยรางวัลจาก streak | ทำงาน → ได้ coin → ใช้ coin → เห็นผลในห้อง |
| 5 | มินิเกม | เกมเดียว (tower defense หรือ survivor) สกินตามธีม, ใช้ coin/แต้มจาก task เป็นเชื้อเพลิง | เล่นจบรอบแล้วบันทึกคะแนนได้ |
| 6 | ธีมที่เหลือ 3 ธีม | Retro Arcade / Coffee Cafe / Wizard Tower / Space Station ครบ 4 | เพิ่มธีมใหม่ได้โดยไม่แก้ logic |
| 7 | ขัดเกลา | PWA ออฟไลน์, ทดสอบมือถือ, เสียง (ทีหลัง), ตัดโค้ด v2 ที่ไม่ใช้ | ติดตั้งเป็นแอปได้ ใช้ออฟไลน์ได้ |

## คำแนะนำลำดับธีม

เริ่มที่ **Space Station**: ห้องในภาพตรงกับหมวดงานชัด (ห้องคอม, ห้องนอน, ห้องนั่งเล่น, ครัว/โต๊ะอาหาร, สวนปลูกพืช, ห้องออกกำลังกาย, โรงรถ) ส่วนธีมอื่นทำตามแม่แบบเดียวกัน

## วิธีทำงานต่อเฟส (workflow)

1. ก่อนเริ่มเฟส: ตกลงขอบเขต + เกณฑ์ "เสร็จเมื่อ" ของเฟสนั้น
2. ทำเป็นก้อนเล็ก ทดสอบบนหน้าเว็บจริง (เดสก์ท็อปก่อน แล้วมือถือ)
3. push เข้า `main` → Pages deploy อัตโนมัติ → ดูผลจริงบน URL
4. จบเฟส: อัปเดตตารางสถานะในไฟล์นี้ และ `CLAUDE.md`
